# CodeLearn Next

Новий окремий застосунок для навчання програмуванню. Працює локально без Firebase, акаунта та зовнішнього перекладача. Старий проєкт не є залежністю.

## Запуск

Потрібні Flutter 3.38.9 / Dart 3.10.8 або сумісні версії. Зафіксовані залежності — у `pubspec.lock`.

```sh
cd codelearn_next
flutter pub get
flutter run -d chrome
```

Рушії практики вже включено в assets. Для їхнього відтворюваного збирання після зміни виконання коду:

```sh
./tool/build_runtime.sh
```

Для вебрелізу з локальними ресурсами рендерингу:

```sh
flutter build web --release --no-web-resources-cdn
python3 -m http.server 8791 --bind 127.0.0.1 --directory build/web
```

Потім відкрити `http://localhost:8791`. Після першого завантаження й кешування браузером доступна робота без мережі; очищення даних браузера видаляє локальний прогрес. Для мобільних збірок усі матеріали та рушії входять до застосунку.

```sh
flutter build apk --debug
flutter build ios --simulator --no-codesign
```

Android APK: `build/app/outputs/flutter-apk/app-debug.apk`. Це тестова збірка; публікація в магазинах і релізне підписування не налаштовані.

## Що працює

- 18 курсів і 145 уроків із теорією, тестами та практикою.
- Відновлення чернетки, етапу уроку й відповідей після перезапуску.
- Український та англійський інтерфейси з типізованими ARB-перекладами, параметрами й множинами.
- Окремий вибір мови навчання з 18 наявних мовних пакетів.
- Адаптивні екрани, темна/світла/системна тема, клавіатурний редактор із підсвічуванням, номерами рядків і автовідступом.
- Локальні XP, рівні, серії днів, досягнення, щоденні нагороди й магазин. Повторне завершення уроку не нараховує нагороду вдруге.
- Буст XP, захист одного пропущеного дня, підказки зі списанням токенів, рамка профілю.
- Карта курсів, завдання дня за фактичними подіями, повторення напрямів із невдалими спробами.
- Портфоліо коду з нотатками й тегами, профіль, аватари, резервне копіювання та об'єднання даних.
- Короткі власні звуки успіху, помилки, завершення, рівня й бонусу; гучність і вимкнення звуку, haptics.
- Локальні щоденні нагадування на Android/iOS після явного ввімкнення та системного дозволу. Вебнагадування не заявляються.
- Локальне збереження звернень підтримки. Без підключення хмари вони нікуди не надсилаються.

## Межі практики

Python виконується через включений Pyodide, JavaScript — у Worker. На мобільних пристроях ті самі мовні ресурси запускаються в окремому headless WebView через локальний сервер, доступний лише на loopback. SQL виконується на ізольованій SQLite-базі з фікстурами; порівнюються результати та зміни стану.

Git і CLI — навчальні симулятори. C++ підтримує підмножину синтаксису наявних вправ і не є повним компілятором. HTML/CSS та React/JSX перевіряються структурно; React не заявляється як повний інтерактивний браузерний preview. Для цих типів вправ потрібні додаткові тестові специфікації при розширенні навчальної програми.

Виконання має обмеження часу й зупинку. Мовний Worker не містить облікових даних. Це локальна практика коду користувача, а не сервіс для запуску недовірених серверних завдань.

## Контент і переклади

`assets/content/en__*.json` містять канонічні уроки, виконуваний код і перевірки. Інші мовні файли містять лише текстові накладки за стабільними ID уроків, слайдів, питань і варіантів відповіді. Переклад не може змінити правильну відповідь або тест.

Імпорт зберіг наявні переклади. 305 перекладів уроків не відповідали актуальному джерелу: вони позначені у `docs/content-import-report.json`, а для них показується цілий англійський урок із поясненням. Якість успадкованих машинних перекладів потребує редакторської перевірки. Наявність мови в списку не означає, що весь контент нею перевірено редактором.

```sh
dart run tool/validate_content.dart
dart run tool/check_content.dart
npm test --prefix tool/runtime
```

Перший інструмент перевіряє структуру й відповідність перекладів, наступні два — усі 145 еталонних рішень. Початкові SQL-фікстури й помилкові очікування CLI history виправлені під фактичне виконання.

## Структура

- `lib/app`: запуск, композиція залежностей, маршрути та життєвий цикл.
- `lib/features/*/domain`: мовонезалежні моделі й правила.
- `lib/features/*/data`: джерела контенту й транзакції локального сховища.
- `lib/features/*/application`: навчальні сценарії між модулями.
- `lib/features/*/presentation`: екрани та спеціалізовані компоненти.
- `lib/design_system`: тема, спільні компоненти, іконографіка.
- `lib/infrastructure`: локальна БД, аудіо, нагадування та контракт синхронізації.
- `lib/l10n`: ARB та згенерований доступ до перекладів.
- `tool/runtime`: джерела мовного Worker та перевірки справжніх мовних рушіїв.
- `integrations/firebase`: окремий необов'язковий пакет хмарних адаптерів.
- `backend`: підготовлені серверні команди та правила, без розгортання.

Локальні дані зберігаються в Sembast: IndexedDB у вебі та файл у каталозі застосунку на мобільних платформах. Завершення уроку, нагорода, досягнення та запис операції виконуються однією транзакцією. Записи портфоліо, сесії й історія мають окремі сховища; список портфоліо завантажується порціями.

## Хмара

За рішенням користувача ця версія локальна. Firebase SDK не входить до основного застосунку, жодні ключі або старі production-конфігурації не перенесені. Пакет `integrations/firebase` можна підключити окремо з перевизначенням контрактів авторизації та синхронізації. Перед його ввімкненням потрібні emulator-тести, правила конфліктів, перевірка квот та налаштування нового середовища. Серверні команди не розгорнуті, реальна міжпристроєва синхронізація не підтверджена.

## Перевірки

```sh
flutter analyze
flutter test
dart run tool/validate_content.dart
dart run tool/check_content.dart
npm test --prefix tool/runtime
npm test --prefix backend/functions
```

Зміни робити в новому проєкті. Згенеровані файли локалізації не редагувати вручну. Після зміни Worker відтворити bundled assets через `tool/build_runtime.sh`.
